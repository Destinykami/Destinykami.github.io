# Personalized Agent

## 一、什么是千人千面Agent

千人千面Agent的核心是让同一个Agent根据不同玩家的偏好、能力、历史行为和当前状态，产生不同但合理的交互策略。

假设我们在一款开放世界 RPG 中设计一名 NPC 队友。

玩家 A 是经验丰富的玩家，喜欢探索和挑战，不希望 NPC 频繁提供提示。

玩家 B 刚开始玩这款游戏，更喜欢剧情交流，希望 NPC 主动提示任务目标。

同一个 NPC 应该呈现不同的交互方式。

|维度|玩家 A|玩家 B|
|---|---|---|
|对话|简洁，少解释基础机制|更详细，更重视剧情|
|任务提示|尽量少主动提示|遇到困难时主动提示|
|战斗协作|偏向高难度配合|偏向保护和引导|
|记忆调用|回顾战术和挑战经历|回顾剧情与人物关系|

但有一个重要约束：**NPC 的核心角色设定不能因为玩家变化而完全失去一致性**。

因此，我们可以把个性化策略写成：

$$ \pi(a_t\mid s_t,g_t,p,u,m_t) $$

其中：

- \(s_t\)：当前游戏状态。
- \(g_t\)：Agent 当前目标。
- \(p\)：NPC 自身的角色设定（Persona）。
- \(u\)：玩家画像，包括能力、长期偏好和短期意图。
- \(m_t\)：当前检索出的相关记忆。
- \(a_t\)：Agent 生成的对话、建议或游戏动作。

这是一个概念性的条件策略表达，不代表实际工程中必须训练一个端到端的策略模型。

## 二、玩家画像构建

### 2.1 玩家画像分类

玩家画像分为两类：长期画像、短期状态

长期画像包括玩家的游戏风格、明确表达的偏好、语言习惯、长期目标、相对稳定的技能水平。
短期状态包括玩家的当前任务、最近的连续失败、当前游戏资源、情绪或意图的推断、近期交互上下文。

两类信息的更新频率不同。比如玩家连续三次任务失败，不一定说明他长期游戏水平低，也可能只是当前副本难度较高。

每条画像最好保留来源、置信度、更新时间和适用范围。对于玩家明确表达的偏好，应当优先考虑，并允许玩家修改或删除。

### 2.2 玩家画像学习与更新

重点讨论三种路线：

|技术路线|典型方法|适用情况|
|---|---|---|
|显式记忆抽取|LLM 信息提取、规则、结构化画像|偏好明确，解释性要求高|
|隐式偏好学习|Embedding、序列建模、偏好模型|玩家具有大量行为日志|
|在线策略调整|Contextual Bandit、RL、策略反馈|需要持续优化交互策略|

在实际业务中，它们通常会组合使用，而非互相替代。

例如，通过事件日志估计玩家是否偏好探索，通过对话记忆获得玩家明确表达的需求，再通过在线反馈调整 NPC 主动提示的频率。

## 三、参考解答：如何构造个性化NPC

我会将个性化 NPC Agent 设计为一个由玩家建模、长程记忆、环境感知、规划决策和反馈更新组成的系统。

首先是玩家建模。将玩家特征分为长期画像和短期状态。长期画像包含游戏风格、交互偏好和技能水平，通过历史行为和玩家明确表达的偏好构建，并进行低频更新。短期状态包含当前任务、近期行为和交互意图，随着游戏状态实时更新。

其次是长程记忆。我会区分原始事件日志和结构化记忆。通过规则或 LLM 提取有价值的事件，形成情景记忆、语义记忆以及可复用的策略经验。检索时综合语义相关性、重要性和时间因素，同时利用元数据过滤保证记忆与当前玩家、游戏场景相匹配。

再次是决策模块。Agent 根据当前游戏状态构建检索请求，获取相关记忆，然后结合玩家画像、NPC 的角色设定和游戏规则，由 LLM 完成高层规划与对话生成。对于具体的游戏动作，我会通过结构化 Action API 和行为树执行，确保实时性、可控性和合法性。

最后通过反馈形成闭环。系统根据玩家行为、明确反馈和任务结果，更新玩家画像和记忆，并评估个性化效果。评测既包含记忆检索准确率、角色一致性等算法指标，也包含玩家满意度、任务成功率、交互延迟和推理成本等业务指标。

对于大规模玩家场景，我会采用共享基础模型、独立的玩家画像与记忆存储的方案，而不是为每个玩家训练单独的模型。
